# Governed Event-to-Forward Intelligence

This capability adds the missing causal layer between source-qualified public events and the existing six-specialist/CIO process without introducing a second decision architecture.

## Operating flow

```text
public event record
→ semantic clustering and source-quality assessment
→ broad causal-analysis admission
→ versioned economic-driver matching
→ target-specific cross-asset transmission
→ point-in-time market confirmation and contradiction checks
→ strict event escalation
→ existing ForwardIntelligenceBundle
→ existing four directional specialists
→ existing six-specialist packet and CIO-only decision
```

## Analysis is not escalation

An event may enter causal analysis when its evidence is not disputed, unverified, or missing and it clears baseline reliability, relevance, and materiality requirements. Analysis does not require a second source, novelty, or an immediate market move.

Specialist/CIO escalation remains stricter. It requires either an authoritative official, regulatory, or issuer source or two independent sources, materiality and novelty thresholds, market confirmation, confirmation coverage, a mapped directional mechanism, and sufficient overall confidence.

An explicit record that supersedes prior evidence receives partial novelty. A repeated record without a substantive update receives zero novelty and cannot escalate.

## Causal behavior

The rule catalog distinguishes causes rather than applying headline sentiment. Examples include:

- conflict escalation versus de-escalation;
- physical supply disruption versus restoration;
- inflation upside versus disinflation;
- monetary easing versus tightening;
- growth improvement versus deterioration;
- corporate upside versus downside;
- financial stress;
- cyber and operational disruption; and
- regulatory approvals versus enforcement.

Several drivers may apply to one event. Opposing material effects for the same target remain `mixed`. A material event without a defensible rule becomes `unresolved_major_event`; it is preserved for review without fabricated direction.

## Existing forward-intelligence integration

Only assessments that clear the strict event and market gates may be converted into `ForwardIntelligenceBundle` records. Those bundles use the production contract already accepted by `ProductionCandidateEvidence`, `CandidateCycleContext`, and the existing specialist service.

The event layer does not create candidates, alter expected returns directly, add a specialist, bypass qualification or the cash hurdle, size positions, construct the portfolio, authorize paper orders, or enable real-money execution.

## Persistence

Event-cluster and event-market assessments are versioned, point-in-time, idempotent, and append-only. Evidence identifiers include the source record, source lineage, corroboration, event cluster, and market observations.
