# Paper-Testing Access Model

Paper testing does not require launch clearance.

The application may begin paper execution as soon as the exact construction can
pass the active technical controls: paper credentials, paper-only endpoint fencing,
current quotes, market session, certified eligible-universe membership, approved
instrument profile, portfolio integrity, liquidity and cost limits, and fill
reconciliation.

The following are not prerequisites for paper testing:

- an immutable launch baseline or process freeze;
- an elapsed burn-in period;
- pre-entry resilience exercises;
- an encrypted recovery certification;
- a paper-launch report;
- an eligibility package;
- a human release-authority decision;
- an activated runtime switch.

Exact authenticated user approval for a proposed portfolio implementation remains
required by the Streamlit approval bridge. This is transaction consent, not launch
clearance. Provider activation, asset eligibility, portfolio safeguards, append-only
evidence, reconciliation, and the prohibition on real-money endpoints remain active.

The legacy campaign, launch, release, and runtime-control authorities remain in the
repository only as optional institutional audit tools. They do not block ordinary
paper testing.
